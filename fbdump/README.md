# fbdump - on-device framebuffer screenshot (PNG)

Small C++ tool that captures `/dev/fb0` and writes a PNG — to a file **or**
to stdout, so a screenshot is one SSH round-trip away:

```sh
ssh root@board fbdump > shot.png          # stdout is binary-clean; info on stderr
ssh root@board 'fbdump -b' | base64 -d > shot.png   # if bytes must cross a pty
fbdump -o /data/now.png                   # local file on the target
```

Zero dependencies: libc + the fbdev ioctls only. The PNG container and the
zlib stream (DEFLATE *stored* blocks, i.e. level-0) are hand-rolled in
`src/main.cpp`, so the tool adds no libpng/zlib to the image image.
`/dev/fb0` is what the glass shows (panel-mipi-dbi streams it verbatim),
so the PNG is display ground truth.

## Device defaults (CMake)

The binary is adapted to our panel at compile time; CLI flags still override:

| knob             | default   | meaning                                  |
|---|---|---|
| `FBDUMP_FB_DEV` | `/dev/fb0` | default framebuffer device (`-d`)         |
| `FBDUMP_WIDTH`  | `142`      | fallback width  (used if the fb ioctl fails / `-g`) |
| `FBDUMP_HEIGHT` | `428`      | fallback height |
| `FBDUMP_BPP`    | `16`       | fallback bpp (16=RGB565, 24/32=X8R8G8B8, 8=gray) |

Pixel format comes from the `FBIOGET_VSCREENINFO` masks at runtime (works for
any LSB-first RGBx layout); the compiled-in geometry is only the fallback.

## Build

```sh
cmake -B build && cmake --build build          # native
cmake -B b -DFBDUMP_FB_DEV=/dev/fb1 ...        # retarget defaults
```

## Tests

```sh
cmake -B btests -DFBDUMP_BUILD_TESTS=ON && cmake --build btests \
  && ctest --test-dir btests --output-on-failure
```

Catch2 v3 (amalgamated, same pin as inv_ctl), gated by `FBDUMP_BUILD_TESTS`
(default OFF — the Yocto build never sees it). Locks down the zero-dep core:
known vectors for crc32/adler32/base64 (incl. the 76-column pty wrap), the
RGB565→888 rescale, and a **byte-exact golden PNG** (`tests/golden_4x4.png`,
generated by the tool from `tests/gradient_4x4.raw`) plus a test that
validates the golden itself so the anchor cannot silently rot. CI: `fbdump`
job in `.github/workflows/firmware.yml`.

```sh
cmake -B build && cmake --build build          # native
cmake -B b -DFBDUMP_FB_DEV=/dev/fb1 ...        # retarget defaults
```

Yocto: recipe `solar-fbdump` (`fw/recipes-apps/solar-fbdump/`) builds this
directory via `file://` SRC_URI, same plumbing as the `inv-ctl` recipe.
Host-side convenience wrapper: `fw/tools/fb-dump.sh` — a thin
`ssh <board> fbdump` wrapper; it checks the tool exists and errors cleanly on
images predating it (the old dd+base64+python fallback is deleted).
